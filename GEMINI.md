# Superrefactoring

Use the skills in `skills/` when the user asks for refactoring research, PR maintainability review, upstream/downstream dependency mapping, or behavior-preserving refactor planning.

Core rules:

- Research before refactoring.
- No code changes during research or planning.
- No output files unless the user explicitly asks.
- Preserve behavior unless the plan clearly labels and justifies a behavior change.
- Delegate implementation to the user's normal development workflow after plan approval.
